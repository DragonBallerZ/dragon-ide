## Agents stay in the folders you opened

**Project Only.** The composer's permission chip has a new mode between Ask and Full Access: **Project Only**. In it an agent works without stopping to ask — it runs commands and edits files on its own — but everything it does stays inside the folders open in the window. Reading, writing, searching or running a command outside them is refused, and nothing from outside them reaches the model. Full Access is now the only mode that reaches the rest of the disk.

**What "inside the folders" means.** The limit holds across every way an agent could step out:

- **File tools and shell commands** (shell sandboxing is macOS) stay in the open folders. A folder you remove from the workspace closes to the agent at once; one you add opens at once.
- **Symbolic links** that point out of the open folders are not followed. Another window's saved output, and the plan folder that every project shares, stay closed — a window sees only the plans written from it.
- **Instruction files and skills** from outside the open folders do not reach the model; Dragon's own still do.
- **A project's own config no longer runs code loose on the disk.** Its `opencode.json` can configure MCP servers, formatters and in-process plugins. Under Project Only (and Ask and Read-Only) a project's **MCP servers** and **formatters** run inside the window's sandbox, and its **in-process plugins** are not loaded. Full Access runs all three unchanged.

## A steadier team

The agent teams from V1.1.4 and V1.1.5 went through a long demo, and this release is the fixes it turned up. Messages between agents hold up under races — duplicates sent again, an agent you stopped, a turn that failed, a message typed just as an approval card appears — and each chat shows an inbound message once, in the sender's words, without the wrapper an agent imitated. Files a lead hands to one agent stay closed to the others, a worktree agent's files reach a teammate only when its branch is merged, and the lead can answer you while it is waiting on its team. New teammates are numbered and placed, and **New Agent** in a team's chat joins that team.

## Install

**macOS:** `DragonIDE-V1.1.6-darwin-arm64.zip` for Apple Silicon and `DragonIDE-V1.1.6-darwin-x64.zip` for Intel. Unzip it and move **Dragon IDE** to Applications. The app is signed with Dragon's Apple Developer ID and notarized by Apple, so it opens like any other app.

**Linux (x64):** `DragonIDE-V1.1.6-linux-x64.deb` for Debian and Ubuntu (`sudo apt install ./DragonIDE-V1.1.6-linux-x64.deb`) or `DragonIDE-V1.1.6-linux-x64.rpm` for Fedora and RHEL (`sudo dnf install ./DragonIDE-V1.1.6-linux-x64.rpm`). Either one adds Dragon IDE to the app menu and a `dragon-ide` command. Or unpack `DragonIDE-V1.1.6-linux-x64.tar.gz` and run `dragon-ide` in the `VSCode-linux-x64` folder.

**Windows (x64):** unzip `DragonIDE-V1.1.6-win32-x64-unsigned.zip` and run **Dragon IDE.exe** in the `VSCode-win32-x64` folder. It is not code-signed yet, so SmartScreen may stop the first launch: click **More info**, then **Run anyway**.

`SHA256SUMS.txt` lists each download's checksum. Local model weights are never bundled; they download only when you pick one in the app. Ollama works on every platform. Splash needs an Apple M3 or newer and macOS 26.4 or newer. Dragon offers a local model only when the machine has the memory for it.

The agent and confinement tests. ## Known issues

- **Confinement's command sandbox is macOS only.** On Linux and Windows, Project Only still keeps an agent's file tools, saved output, plans, links and a project's in-process plugins inside the open folders, but a shell command, MCP server or formatter it spawns is not yet sandboxed to them.
- **Worktrees are not cleaned up.** Each click of the plus in a Git project leaves a worktree and a `dragon/agent-N` branch until you remove them.
- **A teammate's closed chat shows no transcript of turns it ran while closed.** Its work and its report to the lead are unaffected.
- **After you cancel a command, the chat can stay "in progress" for a few seconds.** Reloading the window in that time asks whether to leave the running session.
- **Amazon Bedrock:** choose the **(US)** or **(Global)** model entries, such as **Claude Sonnet 5.5 (Global)**. The plain entries, such as **Claude Sonnet 5.5**, fail with "on-demand throughput isn't supported", because Bedrock serves these models only through cross-region inference profiles.
- **Denying an approval ends the agent's turn.** The agent stops instead of trying another way; send a new message to go on.
- **Answers in Ask mode and Read-Only may say "Plan mode".** Both run OpenCode's plan agent, which calls itself that.

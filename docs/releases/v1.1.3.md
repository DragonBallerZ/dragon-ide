## Long files with Claude on Amazon Bedrock

Claude on Amazon Bedrock can now write a long file in one go. Dragon IDE 1.1.2 sent Bedrock no output limit, so Bedrock stopped each of Claude's replies at 4,096 tokens. A longer file was cut off in the middle of the write, and the write failed with "Invalid arguments for tool "write"". Dragon now sends Claude on Bedrock the model's own output limit, at most 32,000 tokens, which is what Claude gets when you use Anthropic directly. Other models on Bedrock, and every other provider, work as before.

## Install

**macOS:** `DragonIDE-V1.1.3-darwin-arm64.zip` for Apple Silicon and `DragonIDE-V1.1.3-darwin-x64.zip` for Intel. Unzip it and move **Dragon IDE** to Applications. The app is signed with Dragon's Apple Developer ID and notarized by Apple, so it opens like any other app.

**Linux (x64):** `DragonIDE-V1.1.3-linux-x64.deb` for Debian and Ubuntu (`sudo apt install ./DragonIDE-V1.1.3-linux-x64.deb`) or `DragonIDE-V1.1.3-linux-x64.rpm` for Fedora and RHEL (`sudo dnf install ./DragonIDE-V1.1.3-linux-x64.rpm`). Either one adds Dragon IDE to the app menu and a `dragon-ide` command. Or unpack `DragonIDE-V1.1.3-linux-x64.tar.gz` and run `dragon-ide` in the `VSCode-linux-x64` folder.

**Windows (x64):** unzip `DragonIDE-V1.1.3-win32-x64-unsigned.zip` and run **Dragon IDE.exe** in the `VSCode-win32-x64` folder. It is not code-signed yet, so SmartScreen may stop the first launch: click **More info**, then **Run anyway**.

`SHA256SUMS.txt` lists each download's checksum. Local model weights are never bundled; they download only when you pick one in the app. Ollama works on every platform. Splash needs an Apple M3 or newer and macOS 26.4 or newer. Dragon offers a local model only when the machine has the memory for it.

## Checked before release

The agent tests, including a new one for the output limit: Claude on Bedrock gets its own limit up to 32,000 tokens, other Bedrock models and other providers get none, and a limit a plugin sets wins. Desktop tests of first-run setup, of a full chat turn with the usage readout, and of every permission and chat mode, on the packaged app for every download: on GitHub's Linux and Windows runners, and on an Apple Silicon Mac with the Intel build under Rosetta 2. The Mac apps were tested after signing and notarization, and their signatures checked again afterward. `VALIDATION.txt` lists the commit and the runs.

The Apple Silicon build was also run with Claude Sonnet 5.5 on Amazon Bedrock, writing a file of well over 4,096 tokens in one go, checked on disk.

## Known issues

- **Amazon Bedrock:** choose the **(US)** or **(Global)** model entries, such as **Claude Sonnet 5.5 (Global)**. The plain entries, such as **Claude Sonnet 5.5**, fail with "on-demand throughput isn't supported", because Bedrock serves these models only through cross-region inference profiles.
- **Denying an approval ends the agent's turn.** The agent stops instead of trying another way; send a new message to go on.
- **Answers in Ask mode and Read-Only may say "Plan mode".** Both run OpenCode's plan agent, which calls itself that.

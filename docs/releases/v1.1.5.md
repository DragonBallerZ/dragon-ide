## A plus button for new agents, each in its own worktree

**New Agent.** There is a plus in the title of every chat tab and of the Chat panel. Each click opens a new agent in its own chat tab, named `agent-1`, `agent-2` and so on, with Messages on, so the agents you open can message each other straight away. **Dragon: New Agent** in the Command Palette does the same.

**A worktree for each agent.** In a Git project, each new agent gets a Git worktree of its own on a new branch (`dragon/agent-1`, …), made from your current commit, so agents working side by side do not change each other's files or yours. The worktrees are made in `.dragon/worktrees` in your home folder; `dragon.agents.worktreesFolder` changes that. The folder chip under each chat now shows the folder that chat's agent works in. If the folder is not a Git repository, or the mode is Read-Only, the new agent works in the shared folder.

**What to know.** An agent starts from your last commit: changes you have not committed are not in its worktree. Dragon does not merge an agent's branch or remove its worktree; do that with Git when the work is done (`git merge dragon/agent-1`, `git worktree remove <folder>`, `git branch -d dragon/agent-1`). Teammates that a team's lead starts still share the lead's folder.

## Install

**macOS:** `DragonIDE-V1.1.5-darwin-arm64.zip` for Apple Silicon and `DragonIDE-V1.1.5-darwin-x64.zip` for Intel. Unzip it and move **Dragon IDE** to Applications. The app is signed with Dragon's Apple Developer ID and notarized by Apple, so it opens like any other app.

**Linux (x64):** `DragonIDE-V1.1.5-linux-x64.deb` for Debian and Ubuntu (`sudo apt install ./DragonIDE-V1.1.5-linux-x64.deb`) or `DragonIDE-V1.1.5-linux-x64.rpm` for Fedora and RHEL (`sudo dnf install ./DragonIDE-V1.1.5-linux-x64.rpm`). Either one adds Dragon IDE to the app menu and a `dragon-ide` command. Or unpack `DragonIDE-V1.1.5-linux-x64.tar.gz` and run `dragon-ide` in the `VSCode-linux-x64` folder.

**Windows (x64):** unzip `DragonIDE-V1.1.5-win32-x64-unsigned.zip` and run **Dragon IDE.exe** in the `VSCode-win32-x64` folder. It is not code-signed yet, so SmartScreen may stop the first launch: click **More info**, then **Run anyway**.

`SHA256SUMS.txt` lists each download's checksum. Local model weights are never bundled; they download only when you pick one in the app. Ollama works on every platform. Splash needs an Apple M3 or newer and macOS 26.4 or newer. Dragon offers a local model only when the machine has the memory for it.

The agent tests, with a new one that makes two worktrees in a real repository (separate branches at the current commit, uncommitted changes left behind, none outside a repository). ## Known issues

- **Worktrees are not cleaned up.** Each click of the plus in a Git project leaves a worktree and a `dragon/agent-N` branch until you remove them.
- **A teammate's closed chat shows no transcript of turns it ran while closed.** Its work and its report to the lead are unaffected.
- **After you cancel a command, the chat can stay "in progress" for a few seconds.** Reloading the window in that time asks whether to leave the running session.
- **Amazon Bedrock:** choose the **(US)** or **(Global)** model entries, such as **Claude Sonnet 5.5 (Global)**. The plain entries, such as **Claude Sonnet 5.5**, fail with "on-demand throughput isn't supported", because Bedrock serves these models only through cross-region inference profiles.
- **Denying an approval ends the agent's turn.** The agent stops instead of trying another way; send a new message to go on.
- **Answers in Ask mode and Read-Only may say "Plan mode".** Both run OpenCode's plan agent, which calls itself that.

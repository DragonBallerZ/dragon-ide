## Agents that message each other, and teams

Agents in one Dragon IDE window can now send each other messages, and you can start a team of them that works side by side.

**Messages between agents.** Each chat's composer has a new **Messages** chip. It starts off: an agent cannot message anyone, and other agents do not see it. Click it to turn messages on, and the agent can list the window's other agents that have messages on, send one a message, and wait for an answer. A message from another agent starts a turn in the chat it is sent to, shown as **From** and the sender's name with the message quoted. Click the chip again to mute: messages are kept for the agent but do not start a turn.

**Teams.** **Dragon: New Team** asks how many panes you want (2, 3, 4 or 6) and a name, lays the editor area out as a grid, and opens the lead agent's chat in the first pane. Ask the lead for the work; it starts teammates, each in its own pane with its own chat, and they report back to it by message. Only the lead can start teammates. A teammate uses the lead's model and working directory, and if the lead is Read-Only, so is every teammate it starts.

**Staying in control.** Stopping a chat stops that agent: messages from other agents are kept but do not wake it until you send it a message yourself. **Dragon: Stop All Agents** stops every agent in the window. A teammate whose chat is closed still follows the permission mode: in Ask, a notification offers **Allow Once**, **Deny** and **Show Agent**. Two settings cap runaway work: `dragon.agents.maxWakes` (25) is how many turns other agents' messages may start in one agent before you message it or its team's lead again, and `dragon.agents.maxTeammates` (16) is how many teammates a lead may start. A message is at most 16,000 characters, and the same message sent again within a minute is dropped.

## Install

**macOS:** `DragonIDE-V1.1.4-darwin-arm64.zip` for Apple Silicon and `DragonIDE-V1.1.4-darwin-x64.zip` for Intel. Unzip it and move **Dragon IDE** to Applications. The app is signed with Dragon's Apple Developer ID and notarized by Apple, so it opens like any other app.

**Linux (x64):** `DragonIDE-V1.1.4-linux-x64.deb` for Debian and Ubuntu (`sudo apt install ./DragonIDE-V1.1.4-linux-x64.deb`) or `DragonIDE-V1.1.4-linux-x64.rpm` for Fedora and RHEL (`sudo dnf install ./DragonIDE-V1.1.4-linux-x64.rpm`). Either one adds Dragon IDE to the app menu and a `dragon-ide` command. Or unpack `DragonIDE-V1.1.4-linux-x64.tar.gz` and run `dragon-ide` in the `VSCode-linux-x64` folder.

**Windows (x64):** unzip `DragonIDE-V1.1.4-win32-x64-unsigned.zip` and run **Dragon IDE.exe** in the `VSCode-win32-x64` folder. It is not code-signed yet, so SmartScreen may stop the first launch: click **More info**, then **Run anyway**.

`SHA256SUMS.txt` lists each download's checksum. Local model weights are never bundled; they download only when you pick one in the app. Ollama works on every platform. Splash needs an Apple M3 or newer and macOS 26.4 or newer. Dragon offers a local model only when the machine has the memory for it.

## Checked before release

The agent tests, with new ones for the message rules (opt-in, mute, stop, the size limit, repeats, the wake and teammate caps, Read-Only inheritance, only the lead starts teammates) and an end-to-end test against the real OpenCode server. A new desktop test drives a team through a scripted model, and passed on both notarized Mac downloads (it has not been run on Linux or Windows): a new team, a teammate started by the lead, its report back, a stopped teammate that stays stopped, a teammate with a closed chat under Full Access and under Ask, a window reload, and the Messages chip. `VALIDATION.txt` lists the commit and what ran on each download.

## Known issues

- **A teammate's closed chat shows no transcript of turns it ran while closed.** Its work and its report to the lead are unaffected.
- **After you cancel a command, the chat can stay "in progress" for a few seconds.** Reloading the window in that time asks whether to leave the running session.
- **Amazon Bedrock:** choose the **(US)** or **(Global)** model entries, such as **Claude Sonnet 5.5 (Global)**. The plain entries, such as **Claude Sonnet 5.5**, fail with "on-demand throughput isn't supported", because Bedrock serves these models only through cross-region inference profiles.
- **Denying an approval ends the agent's turn.** The agent stops instead of trying another way; send a new message to go on.
- **Answers in Ask mode and Read-Only may say "Plan mode".** Both run OpenCode's plan agent, which calls itself that.

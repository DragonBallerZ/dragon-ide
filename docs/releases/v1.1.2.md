## Dragon IDE, by name

Dragon IDE 1.1.2 greets you by name: the entrance and the Welcome page are now headed **Dragon IDE** instead of FREEDOM AI. The **Enter FREEDOM AI** button works as in 1.1.1.

## Permission modes that do what they say

- **Ask first** (the default) now asks before the agent edits a file or runs a command. In 1.1.1 it never asked, and picking **Allow once** or **Always allow** in an approval counted as **Deny**.
- **Ask** mode is now in the mode picker. It runs OpenCode's plan agent, which reads, searches and plans but does not change your files.
- **Read-Only** runs no command and changes no file, in any mode, even after an earlier **Always allow**.
- Approvals from the agent's helper subagents come to your chat instead of being dropped.
- A denied command reads **Skipped** in the chat instead of **Ran**.

## Install

**macOS:** `DragonIDE-V1.1.2-darwin-arm64.zip` for Apple Silicon and `DragonIDE-V1.1.2-darwin-x64.zip` for Intel. Unzip it and move **Dragon IDE** to Applications. The app is signed with Dragon's Apple Developer ID and notarized by Apple, so it opens like any other app.

**Linux (x64):** `DragonIDE-V1.1.2-linux-x64.deb` for Debian and Ubuntu (`sudo apt install ./DragonIDE-V1.1.2-linux-x64.deb`) or `DragonIDE-V1.1.2-linux-x64.rpm` for Fedora and RHEL (`sudo dnf install ./DragonIDE-V1.1.2-linux-x64.rpm`). Either one adds Dragon IDE to the app menu and a `dragon-ide` command. Or unpack `DragonIDE-V1.1.2-linux-x64.tar.gz` and run `dragon-ide` in the `VSCode-linux-x64` folder.

**Windows (x64):** unzip `DragonIDE-V1.1.2-win32-x64-unsigned.zip` and run **Dragon IDE.exe** in the `VSCode-win32-x64` folder. It is not code-signed yet, so SmartScreen may stop the first launch: click **More info**, then **Run anyway**.

`SHA256SUMS.txt` lists each download's checksum. Local model weights are never bundled; they download only when you pick one in the app. Ollama works on every platform. Splash needs an Apple M3 or newer and macOS 26.4 or newer. Dragon offers a local model only when the machine has the memory for it.

## Checked before release

The agent, search, provider and usage tests, including an end-to-end run of the real OpenCode agent. Desktop tests of first-run setup, which now check both headings, of a full chat turn with the usage readout, and of every permission and chat mode (approve, deny, Ask mode, Read-Only, Full Access, each checked on disk), on the packaged app for every download: on GitHub's Linux and Windows runners, and on an Apple Silicon Mac with the Intel build under Rosetta 2. The Mac apps were tested after signing and notarization, and their signatures checked again afterward. `VALIDATION.txt` lists the commit and the runs.

After publishing, the Apple Silicon download was also run with real models, Claude Opus 5.5 and Claude Sonnet 5.5 on Amazon Bedrock: planning in Ask mode, carrying the plan out with approvals, a denied command, Read-Only and Full Access all behaved as described above, each checked on disk.

## Known issues

- **Amazon Bedrock:** choose the **(US)** or **(Global)** model entries, such as **Claude Sonnet 5.5 (Global)**. The plain entries, such as **Claude Sonnet 5.5**, fail with "on-demand throughput isn't supported", because Bedrock serves these models only through cross-region inference profiles.
- **Claude on Amazon Bedrock stops each reply at 4,096 tokens.** Writing a long file in one go can then fail with "Invalid arguments for tool "write"". Fixed in 1.1.3.
- **Denying an approval ends the agent's turn.** The agent stops instead of trying another way; send a new message to go on.
- **Answers in Ask mode and Read-Only may say "Plan mode".** Both run OpenCode's plan agent, which calls itself that.
